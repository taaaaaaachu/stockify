# ADR 0008: ストック品目の商品リンク

- Status: Accepted
- Date: 2026-08-08

## Context

同じストック品目を購入できるAmazon、楽天市場、メーカー公式通販などの販売ページを、品目ごとに複数保存したい。購入履歴や定期便は購入イベントの記録・推定に使うため、販売ページの情報をそれらへ混在させない。

## Decision

ストック品目に複数の「商品リンク」を紐づける。商品リンクは任意の表示名と必須URLの組で、`http` / `https` のみを許可する。表示名は最大100文字、URLは最大2,048文字とする。表示名が空欄の場合はURLのホスト名を表示する。

リンクには品目内の順序を持たせ、ユーザーが上へ・下へ操作で並べ替える。先頭を既定リンクとし、既定リンクの削除後は残った先頭を既定リンクにする。同一品目内の同一URLは重複登録しない。リンク数には上限を設けない。

ゲストIndexedDB、会員SQLite/API、エクスポート/インポートで同じ商品リンクモデルを扱う。新規作成画面と品目詳細画面で管理し、ダッシュボードと買い物リストでは既定リンクだけ表示する。外部リンクは新しいタブで開く。

## Consequences

商品リンクは購入履歴や消費レート計算に影響しない。既存データには商品リンクがないため、移行後も空のリンク一覧として扱える。順序を保存するため、単純な文字列配列ではなく、IDを持つ子レコードを採用する。

## Alternatives considered

- 品目にURLを1本だけ持つ: 複数の販売先を扱えない。
- URLのJSON配列を品目列へ保存する: 個別削除・並べ替え・重複制約・将来の表示名追加が扱いにくい。
- 購入イベントへURLを持たせる: 商品リンクが購入履歴へ誤って結びつき、同じ品目の購入先一覧として使いにくい。
