# ユーザーの即時削除と世帯データの維持

## ステータス

採用

## 決定

ユーザー削除は、`super_admin`による他ユーザー削除と、ロールに関係なく本人による自分自身の削除を提供する。managerやmemberの自己削除を許可し、他ユーザーのアカウント削除は`super_admin`に限定する。世帯からの除名・脱退とアカウント削除は分離する。

削除は即時・完全削除とし、復元機能は設けない。本人または操作するsuper_adminの現在のパスワードと、削除対象ユーザー名の入力をサーバー側で検証する。最後のsuper_adminは削除できない。

削除時のデータ扱いは次のとおりとする。

- ユーザー、所属、全セッションを削除する。
- 世帯、ストック品目、購入、定期便、補正など世帯所有のデータは維持する。
- 招待コードの発行者・使用者はnullにして履歴を維持する。
- 削除対象ユーザーがownerの世帯を持つ場合は削除を拒否する。owner交代申請が保留中なだけでは交代完了とみなさない。
- 削除対象ユーザーが他世帯のowner交代候補になっている場合は、その保留申請を自動キャンセルする。

## 背景・理由

在庫はユーザー個人ではなく世帯が所有しているため、ユーザー削除に連動して世帯の共有在庫を消すと、他の所属ユーザーのデータを破壊してしまう。世帯のownerだけは世帯運営に必要なため、交代完了前の削除を防ぐ。削除後も招待の履歴は残すが、削除済みユーザーの個人情報は参照できないようにする。

## 帰結

- アカウント画面に本人削除の確認導線が必要になる。
- super_adminのユーザー管理画面に他ユーザー削除の導線が必要になる。
- owner世帯の確認、最後のsuper_admin判定、パスワード検証、関連データ削除を1トランザクションで行う必要がある。
