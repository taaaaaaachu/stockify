# 強制パスワード変更はパスキー登録でも解除でき、パスワードを決めないリセットリンクも用意する

## ステータス

採用(ADR 0004 と ADR 0010 の一部を置き換える)

## 決定

- 管理者リセットの一時パスワードは従来どおりサーバーが生成し、常に強制パスワード変更の状態にする(ADR 0004)。
- 強制パスワード変更中の会員は、次のどちらかを済ませるまでログアウト以外の操作ができない。
  - (a) 一時パスワードと異なる新しいパスワードを設定する。
  - (b) パスキーを登録する。一時パスワードは削除され、パスキーのみの会員になる。
  - ADR 0010 の「強制パスワード変更中はパスキーの操作も本人確認もできない」を置き換え、パスキーの登録と、その前の本人確認だけは許す。
- 強制変更では現在のパスワードの再入力を求めず、**直近の本人確認**で代える。ログイン直後なら済んでいる。時間が経っていれば一時パスワードで本人確認を挟む。ADR 0004 の「一時パスワードでのログインを本人確認とみなす」を、この期限付きの扱いに改める。一時パスワードと同じ新パスワードは拒否する。
- 強制はサーバー側で行う。ページはアカウント画面へ戻し、API は変更に必要なもの(パスワード変更・パスキー登録・その前の本人確認)以外を 403 にする。世帯や在庫のデータも返さない。
- super_admin は一時パスワードの代わりに**リセットリンク**を発行できる。
  - 認証情報の初期化(パスワード・全パスキー・全セッション)は**発行時ではなくリンクを使った時点**で行う。
  - リンクを開いた本人は、新しいパスワードかパスキーのどちらかを設定し、その端末でそのままログインする。設定したパスワードは強制変更の対象にしない。
  - 有効期限は 24 時間固定で、1 回使うと消費する。1 人につき最新の 1 本だけが有効で、再発行や一時パスワードの発行をすると未使用の古いリンクは使えなくなる。
  - トークンは DB にハッシュで保存し、URL は発行直後に一度だけ表示する。未使用のリンクは取り消せる。
  - 発行後に対象者や発行者のロールが変わっても有効のまま。対象者が削除されたときだけ消える。
  - 強制パスワード変更中の会員でもリセットリンクのページは開ける(同じブラウザで別の人のリンクを開く場合のため)。
- 対象にできる範囲は既存の管理者リセットと同じで、super_admin が自分以外のユーザーに対して行う。

## 背景・理由

- ADR 0010 で強制変更中のパスキー登録を禁じたのは、変更の流れを1本にするためだった。しかしリセットで復旧するのはパスキーを主に使う会員が多く、一度パスワードを決めてから登録し直す手間は大きい。一時パスワードを消してパスキーだけにすれば、管理者が知っているパスワードは残らないので目的は果たせる。
- セッションは最長 30 日続く。一時パスワードでログインしたまま放置された端末から、いつまでも本人確認なしで変更できる状態は残したくない。一方、ログイン直後にもう一度入力させても防げるものはないので、直近の本人確認で代える。
- 発行時に初期化すると、本人がリンクを使わなかった・送り間違えた場合に、本人のログインを無駄に壊してしまう。乗っ取りの疑いがあって即座に締め出したいときは一時パスワードの発行を使えばよい。
- 使用時にロールを確かめ直すと、発行後の昇格だけで復旧できなくなる。期限が短く取り消しもできるので、発行時点の権限で十分とした。

## 帰結

- リセットリンクの URL は管理者がメッセージアプリなどで本人に渡す(メールは送らない。ADR 0004)。URL を見失ったら再発行する。
- reset_links テーブルを追加する。users の削除で行が消える。
