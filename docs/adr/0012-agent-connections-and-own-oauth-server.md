# エージェント接続は世帯1つに限り、MCP と自前の OAuth 2.1 認可サーバーで提供する

## ステータス

採用

## 決定

- 自律型 AI エージェントには **エージェント接続** を通して在庫を操作させる。1件の接続は、発行した会員と**世帯1つ**に結びつく。
  - 作り方は2通りある。OAuth 2.1 の同意画面で作るものと、アカウント画面で手動発行する Bearer トークン。どちらも同じ一覧で管理し、取り消し方も同じ。
  - 権限の段階は設けない。その世帯の在庫(品目・購入・使い切り・残量補正・定期便・商品リンク)はすべて操作できる。発行者が owner の接続だけ、世帯設定も変更できる。
  - 権限は発行時ではなく、発行者の**その時点の**世帯内ロールで判断する。
  - 世帯・所属・招待・アカウントの操作はできない。エージェントが作った記録に印は付けない。
- 入口は `/mcp` の1本だけ。MCP の Streamable HTTP をステートレスで動かす。トークンは `/mcp` 以外(`/api/*`)では受け付けない。
- OAuth 2.1 の認可サーバーはアプリ内に自前で持つ。
  - クライアント登録は Client ID Metadata Document(CIMD)と Dynamic Client Registration(DCR、RFC 7591)の両方に対応する。
    - CIMD: 任意の https の `client_id` を受け付けるが、メタデータの取得には SSRF 対策を入れる。
    - DCR: 誰でも登録できる。戻り先は https かループバックの http だけ。認証方式は何を求められても公開クライアント(none)で登録する。接続に使われないまま30日過ぎた登録は消す。
    - DCR のクライアントは身元をドメインで確かめられないので、同意画面では戻り先のドメインを身元として示す。
  - `redirect_uri` は文書に列挙されたものと完全一致のときだけ受け付ける。ループバックの http も許す。PKCE は S256 だけ。
  - アクセストークンは寿命1時間の不透明トークン。リフレッシュトークンは使うたびに入れ替え、古いものが再び使われたら接続ごと失効させる。
  - トークンはすべて DB にハッシュで保存する。
- 接続を作るときは本人確認を求める。
- 接続は次のときに消える。
  - 90日間使われなかったとき
  - 発行者がその世帯から外れたとき
  - アカウントを削除したとき
  - 管理者からパスワードリセットを受けたとき
- 本人のパスワード変更やパスキーの削除では接続は消えない。強制パスワード変更中は接続を使えない。
- SvelteKit 組み込みの CSRF 判定を止め(`csrf.trustedOrigins: ['*']`)、同じ判定を hooks で行う。除外は `/oauth/token` と `/oauth/revoke` だけ。
  - OAuth の仕様では、この2つはエージェントのサーバーから Origin なしのフォーム POST で呼ばれる。SvelteKit の判定は Origin なしも拒否するうえ、パス単位で除外できない。
  - どちらも Cookie を読まず、認可コード+PKCE かリフレッシュトークンだけで認証するので、除外しても CSRF は成り立たない。
  - adapter-node を包む自作サーバーで、この2つのパスにだけ Origin を足す案も検討した。しかし、焼き込んだ `paths.origin` とオリジンの算出方法をビルドの外に書き写す必要があり、起動方法も変わるので採らなかった。
  - SvelteKit がパス単位の除外に対応したら、自前の判定はやめて組み込みに戻す。

## 背景・理由

- エージェントは間違える。世帯を固定しておけば、「自宅」と「別の家」の取り違えを仕組みの上で防げる。
- 画面向けの `/api/*` は Cookie での世帯切り替えや本人確認(428)を前提にしている。トークンを `/mcp` だけに絞れば、「エージェントにできること」がツール一覧と一致する。
- 認可サーバーをライブラリ(oidc-provider など)や外部サービス(Cloudflare Access、Auth0 など)に任せなかった理由は次のとおり。
  - 既存のパスワード・パスキー・本人確認・強制パスワード変更・試行制限と、同意画面での世帯選択を噛み合わせる必要がある。
  - トークンの寿命の規則がこのアプリ固有である。
  - 必要な機能は MCP の仕様が求める範囲に限られ、自前で書いても小さい。
- 当初は CIMD だけにした。MCP 仕様(2025-11-25)が推奨しており、サーバー側にクライアントを保存せずに済むからだった。しかし、使いたいエージェント(muse)が DCR にしか対応しておらず OAuth で繋がらなかったため、DCR も受け付けることにした。
  - 誰でも登録できても、実際に使えるのは本人がログイン・本人確認のうえ同意した後だけなので、登録の開放そのものは危険ではない。溜まり続けないよう、使われない登録は消す。
- パスワードリセットは乗っ取りからの復旧手段なので、乗っ取った人が作った接続を残さないよう消す。本人によるパスワード変更では消さない。日常の変更でエージェントが毎回切れると不便だからで、気になれば一覧から取り消せる。

## 帰結

- oauth_clients テーブルを追加する(DCR の登録)。
- 世帯設定の API は、これまで member でも変更できた(用語集と食い違っていた)。これにあわせて owner 限定に改める。
