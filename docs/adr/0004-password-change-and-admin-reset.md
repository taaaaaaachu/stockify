# パスワード変更とインスタンス管理者によるリセット

## 決定

ユーザー自身のパスワード変更と、`super_admin` による他ユーザーのパスワードリセットを分けて提供する。

- 本人変更では現在のパスワードを必須にする。
- 新しいパスワードは8〜256文字とし、確認入力との一致もサーバー側で検証する。
- 本人変更後は現在のセッションを維持し、それ以外の同ユーザーのセッションを無効化する。
- 管理者リセットは `super_admin` のみ実行でき、自分自身は対象にできない。
- リセット時はサーバーがランダムな一時パスワードを生成し、対象ユーザーの全セッションを無効化する。
- 一時パスワードはレスポンスと画面上で一度だけ扱い、DBにはArgon2ハッシュだけを保存する。
- リセットされたユーザーには `must_change_password` 状態を設定する。
- 強制変更中はログアウトまたはパスワード変更以外のページ・APIを拒否し、本人変更成功時に状態を解除する。

## 背景・理由

パスワード変更は本人が現在の認証情報を持っていることを確認する必要がある。一方、パスワードを忘れた場合の復旧には管理者によるリセットが必要だが、管理者が任意の平文パスワードを決めると共有・再利用されやすい。そのため一時パスワードをサーバー生成し、次回ログイン時の変更を必須にする。

アカウントは世帯をまたいで利用されるため、世帯ownerには他ユーザーのパスワードリセット権限を与えず、インスタンス全体を管理する `super_admin` に限定する。

## 帰結

- users テーブルは管理者リセット後の強制変更状態を保持する。
- セッション無効化はパスワード更新と同じトランザクションで行う。
- 管理者リセット後に残存セッションから通常APIを呼び出されることを、サーバー側の強制変更チェックで防ぐ。
- メール送信や自動パスワードリカバリーはこの機能の範囲外とし、一時パスワードの伝達は管理者が安全な経路で行う。
